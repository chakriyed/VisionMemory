# VisionMemory

An AI-powered visual memory system. It watches a room through your webcam, detects
and tracks objects you register (headphones, wallet, keys, USB drive, etc.), and
remembers where and when it last saw each one — with a saved camera frame as
evidence. You can then ask natural-language questions like:

- "Where did I last see my headphones?"
- "What happened to my wallet after I left the room?"

and get an answer grounded in the actual stored frames, generated by Claude's
vision model.

## How it works

1. **Register** an object by pointing the camera at it and giving it a name
   (e.g. "headphones"). No training required — detection uses
   [YOLO-World](https://docs.ultralytics.com/models/yolo-world/), an
   open-vocabulary detector, so any object name you type becomes a live
   detection class via a text prompt.
2. **Watch**: the browser streams webcam frames to the backend roughly once a
   second. Each frame is run through YOLO-World + ByteTrack (built into
   Ultralytics) to detect and track your registered objects.
3. **Memory**: when an object is seen, a timestamped "seen" event + annotated
   frame is stored (throttled to avoid flooding storage). If a tracked object
   isn't seen again for a few seconds, a "disappeared" event is logged with its
   last known position and frame — this is what lets the system answer
   "what happened after I left" style questions.
4. **Query**: your question is matched to a registered object, the most recent
   evidence frames for it are pulled from storage, and sent to Claude
   (vision-capable) along with the question. Claude answers using only that
   visual evidence and the response includes the frames it used.

## Project layout

```
backend/
  app/
    main.py       FastAPI app + HTTP routes
    detector.py   YOLO-World detection + tracking wrapper
    tracking.py   In-memory tracking state -> throttled DB events
    db.py         SQLite schema + queries
    storage.py    Frame encode/decode/save helpers
    vlm.py        Claude API query answering
    config.py     Settings (env-var overridable)
  requirements.txt
frontend/
  index.html, app.js, style.css   Single-page UI (webcam, registration, chat)
data/
  visionmemory.db   SQLite database (created on first run)
  frames/           Saved evidence frames, one subfolder per object
  references/        Reference photo captured at registration time
```

## Setup

Requires Python 3.10+ and a webcam-capable browser (camera access needs a
secure context — `localhost` is fine).

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env` in the project root (or just export the vars) and
set your Anthropic API key:

```bash
cp .env.example .env
# edit .env and set ANTHROPIC_API_KEY=sk-ant-...
```

Without `ANTHROPIC_API_KEY`, detection/tracking/storage still work, but
`/api/query` falls back to returning the raw event log instead of a
Claude-generated answer.

## Run

```bash
cd backend
source .venv/bin/activate
export $(grep -v '^#' ../.env | xargs)   # or use your own env loading
uvicorn app.main:app --reload --port 8000
```

Then open **http://localhost:8000** in a browser, allow camera access, and:

1. Click **Start Camera**.
2. Point it at an object, type a name, click **Capture & Register**.
3. Click **Start Watching** to begin live tracking.
4. Ask a question in the bottom panel.

### Notes

- First run downloads the YOLO-World weights (`yolov8s-world.pt`, a few tens
  of MB) from Ultralytics — needs internet access once.
- Detection quality for small/uncommon objects (like keys or a USB drive) can
  be inconsistent since YOLO-World is zero-shot / not fine-tuned on your
  specific items. Registering with a clear, well-lit reference shot and
  keeping the object reasonably prominent in frame helps.
- This is a single-camera, single-process prototype: state (active tracks) is
  kept in memory, and storage is local SQLite + JPEG files on disk — not
  designed for multi-camera or multi-user deployment as-is.
